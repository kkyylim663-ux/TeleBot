# Tele Bot（Bot 计算机）产品说明文档

> 本文档基于对源码 `Bot 计算机.txt`（单文件 Python，约 3300 行，基于 python-telegram-bot v20+）的实际分析撰写。

---

## 一、产品定位

**Tele Bot 是一套部署在 Telegram 上的群组运营助手机器人**，把三类日常运营工作集中到一个 Bot 里完成：

1. **群发广播** —— 向一批已登记的群/频道批量推送文案（即时 / 定时 / 每日循环）。
2. **群记账账本** —— 在群里用最简单的消息格式（`+100`、`-50`、`下发 2000`）实时记流水账，自动算费率、汇率、GrandTotal，并支持账期结算与 Excel 导出。
3. **租户到期管理** —— 登记设备/空间的租约（金额、合约期数、续费周期），自动在到期前提醒、逾期升级@负责人、一键续租/退租。

从功能组合看，典型使用场景是**设备/空间出租类业务的运营团队**：管理员在一个后台私聊里管理目标群和文案，各个业务群里成员直接发消息记账，租约到期由 Bot 自动盯梢提醒。

## 二、角色与权限模型

| 角色 | 判定方式 | 能做什么 |
|---|---|---|
| **超级管理员（Owner，代码中称 admin）** | 用户名硬编码在 `ADMIN_USERNAMES`（共 5 个：IgAccJohn、Dragonball77、MrK6776、IgCsLyn、jiang9546），大小写不敏感 | 一切功能：授权管理、目标管理、群发、租户登记/管理、清空账单、自动结算设置、欢迎语设置 |
| **授权用户** | 记录在 `authorized_users.json`（按数字 ID 或 @用户名），可由管理员通过 `/adduser` 添加 | 基础交互：`/start` 主菜单、记账相关指令、到期提醒卡片上的「续租/退租」按钮 |
| **普通成员** | 其他所有人 | 无任何响应（所有入口都有 `is_authorized` / `is_admin` 拦截） |

授权判定函数：`is_admin()`、`is_authorized()`（管理员自动视为已授权）。

## 三、核心功能模块

### 1. 群发广播

- **目标群登记**（`/addtarget`）：Bot 会自动追踪自己出现过的所有群/频道（`known_groups.json`），登记时直接按钮选择，也可手动输入群 ID（不知道 ID 可用 `/whereami` 查询）；自动抓取真实群名，并支持起自定义备注名。
- **分组/分类管理**（`/listtargets`）：每个目标可属于多个分类（groups）；分类界面支持新建分类、勾选成员、翻页矩阵式编辑；可一键「刷新群名」同步真实群名。
- **文案库**（`/adddraft`、`/listdrafts`）：保存常用群发文案模板，支持名称 + 内容，删除有确认。
- **发送流程**（`/broadcast`，四步向导）：
  1. 时间方式：立即发送 / 单次定时（YYYY-MM-DD HH:MM）/ 每日固定时间循环；定时计划可保存复用（Schedule 列表可增删）。
  2. 选择目标分组或全部分组。
  3. 选择文案来源：临时编写或从文案库选。
  4. 汇总确认后启动。
- **发送报告**：完成后私聊报告成功/失败数量与失败详情；群升级为超级群导致 ID 变化时（`ChatMigrated`）自动改用新 ID 发送并回写目标库。

### 2. 群记账账本（在群里直接发消息即可）

**记账指令（中文关键词，正则匹配）：**

| 写法 | 含义 |
|---|---|
| `+100 客户老王` | 记一笔入账（可带备注） |
| `-50 提现` | 记一笔出账 |
| `下发 2000` / `下发 -2000 手续20 备注` | 记下发，支持单独指定手续费 |
| `撤销` / `撤销恢复`（回复某条记账消息） | 作废 / 恢复该笔记录 |
| `账单` 或 `/ledger` | 查看当前账单（紧凑视图：每类最近 5 笔 + 汇总） |
| `结束账单` | 结算本期，GrandTotal 结转到下期，账期 +1 天 |
| `撤销结束账单` | 回滚最近一次结算 |
| `清空账单` / `撤销清空账单` | 作废本期全部记录 / 恢复 |
| `设定日期 YYYY-MM-DD` | 手动校准账期显示日期 |
| `导出账单` | 生成近 30 天 Excel（openpyxl）发回群里 |
| `设置自动结算时间 HH:MM` / `取消自动结算` | 全局每日自动结算（仅管理员） |

**每群独立设置：**

- `设置入账费率 X` / `设置出账费率 X`：入账按 % 扣减、出账按 % 加成，账单里以带上标数字（如 `100 ² = 98`）显示。
- `设置AUD汇率 1.5` / `设置USDT汇率 /6.5`：多币种汇率，支持乘法或除法两种模式；出现多币种时账单自动切换为按币种分组显示。
- `设置币种 USDT`、`设置时区 8`、`设置手续费 X`（下发为负数时的固定手续费，可用「手续X」按笔覆盖）。
- `记账设置`：查看当前全部参数。

**账期机制**：每个群有自己的账期（period_start / period_label），记账累积在当前账期内；「结束账单」时计算 `结转余额 + 入账 − 出账` 得到各币种 GrandTotal 并结转，支持快照式撤销。

### 3. 租户到期管理

- **批量登记**（`/duedate`，仅管理员）：三步向导——选群 → 逐行输入「设备名 开始日期(YYYY-MM-DD) 金额 合约期数」（可分多条消息、错行单独重填）→ 选续费周期（一次性/每月/每周/每年/自定义天数）。
- **项目管理**（`/listduedate`）：按群进入，分页矩阵勾选，支持批量「退租」、单个项目「改金额 / 改合约期数」。
- **列表查询**：在群里发「租户列表」按到期日排序展示全部项目。
- **每日自动扫描**（UTC+8）：
  - **12:00**：到期前 1 天的项发「明日到期提醒」卡片（带 ✅续租 / 🚪退租 按钮）；已逾期 1 天且无人处理的项**自动默认续租**并推进期数与到期日，群里通知。
  - **15:00**：对仍未处理的项升级提醒，@登记人（creator）催办。
  - 启动时会立即补跑两轮扫描，另有 `ddtest1200` / `ddtest1500` 手动触发命令。

### 4. 辅助功能

- **新人欢迎**（全局）：`设置欢迎语 内容`（支持 `{name}`、`{group}` 变量）、`开启欢迎` / `关闭欢迎` / `查看欢迎语`；新成员进群自动回复。
- **简易计算器**：纯数字与 `+ - * / ( )` 的算式直接返回结果（内部 `eval`，已做字符白名单）。
- `/whereami`：查询当前聊天室 ID。
- `/start`：呼出主菜单键盘（使用说明 / 联系客服 / 个人中心 / 群发广播 / 续费空间 / 全局账单）。
- `/cancel`：终止任何进行中的问答式会话（ConversationHandler 统一 fallback）。
- 「使用说明」内置完整指令帮助文档。

## 四、数据存储

全部状态以 JSON 文件持久化在 `/app/` 目录（无数据库），均为「读时加载、写时全量保存」：

| 文件 | 用途 |
|---|---|
| `authorized_users.json` | 授权用户（ids + usernames） |
| `known_groups.json` | Bot 自动追踪到的群/频道清单 |
| `broadcast_targets.json` | 群发目标（群 ID → 真名/备注/分类） |
| `broadcast_drafts.json` | 群发文案库 |
| `broadcast_schedules.json` | 定时发送计划 |
| `tenants.json` | 租户项目（按群分桶：设备/金额/期数/周期/到期日/状态） |
| `ledger_settings.json` | 每群记账参数（费率/汇率/币种/时区/账期） |
| `ledger_entries.json` | 记账流水（按群分桶） |
| `ledger_carryover.json` | 每群结转余额（按币种） |
| `ledger_close_snapshot.json` | 「结束账单」撤销快照 |
| `ledger_clear_snapshot.json` | 「清空账单」撤销快照 |
| `ledger_global.json` | 全局自动结算时间 |
| `welcome_settings.json` | 全局欢迎语配置 |

## 五、已知问题与风险（供维护参考）

1. **🔴 Bot Token 硬编码在源码第 17 行**。此 Token 已随文件明文存在，存在泄露风险，建议立即改为环境变量（`os.environ["BOT_TOKEN"]`）并到 @BotFather 重置 Token。
2. **🔴 主消息分发链断裂**：`handle_message` 中处理「联系客服」后直接 `return`，导致其后的「个人中心 / 续费空间 / 全局账单」菜单分支以及**全部记账处理链**（记账设置、撤销、+金额记账、下发、欢迎语设置、计算器）代码永远不可达。目前群里记账实际不可用，需将「联系客服」分支也 `return` 之外的结构修正（该分支后的代码全部被短路）。
3. **🟠 `记账设置` 查看指令会崩溃**：代码引用了已被多币种重构淘汰的 `s["rate_mode"]` / `s["rate"]` 键，触发即 `KeyError`。
4. **🟠 `try_handle_ledger_disburse` 中存在 return 之后的死代码**（重复的落账逻辑），应删除。
5. **🟡 计算器使用 `eval`**：虽有字符白名单（数字与四则运算符），仍建议替换为 `ast` 安全求值。
6. **🟡 所有 JSON 读写无锁**：`concurrent_updates(True)` 下高频操作可能产生竞态；数据量大时每条消息全量重写文件也有性能问题。
7. **🟡 单次定时/每日群发任务只存在于内存 JobQueue**：进程重启后未触发的定时任务会丢失（Schedule 定义有落盘，但已排队的 job 不恢复）。
